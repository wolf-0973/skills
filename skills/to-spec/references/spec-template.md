# Spec template

```markdown
## Problem Statement

The problem that the user is facing, from the user's perspective.

## Solution

The solution to the problem, from the user's perspective.

## User Scenarios

A LONG, numbered list covering all aspects of the feature. Each:

1. As a <role>, I want <capability>, so that <benefit>.

## Implementation Decisions

- Modules or interfaces to build or modify
- Architectural decisions, schema/API contracts, interactions
- Developer clarifications

## Testing Decisions

- What makes a good test: external behavior only
- Which modules / seams will be tested
- Prior art for similar tests in the repo

## Out of Scope

## Further Notes
```

Do NOT include specific file paths or code snippets — they go stale quickly.

Exception: a code snippet may be inlined only when the snippet itself encodes the decision, such as a state machine, reducer, schema, or type shape. Trim it to the decision-rich part.
